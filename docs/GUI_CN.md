# 模块化训练 / 推理控制台

启动：

```bash
python launch_gui.py
```

请使用已经安装本项目 PyTorch、torchvision、Pillow 等依赖的 Python 环境。

填写配置后，点击右侧顶部「运行与反馈」标题下方的「▶ 开始运行」按钮启动训练或推理。
修改界面代码后，需要关闭旧窗口并重新运行 `python launch_gui.py` 才会显示新版布局。

## 设计方式

界面没有“SPIF 训练脚本”“CUT 推理脚本”一类固定工作流。它只有两个稳定入口：

- `training/train.py`：统一训练引擎。
- `inference/infer.py`：统一单向生成器推理引擎。

模型和数据集分别由 `--model`、`--dataset_mode` 选择。界面从
`models/registry.py` 读取已实现的组合，并发现自定义模型与 `data/*_dataset.py`，再调用模块自己的
`modify_commandline_options`，因此模型新增或调整参数后不需要复制一套 GUI 表单。
推理时，`--model test` 是通用运行器，`--source_model` 指明检查点来自哪个训练模块；
后者会提供与训练时一致的生成器默认值和结构参数。

## 界面分层

主界面只要求依次确认：

1. 任务：训练或推理。
2. 模型的四个组成元素：架构 → 输入类别 → 融合策略 → 额外损失。
3. 数据模块。
4. 数据路径、实验名、设备等必要信息。
5. 通道、尺寸、批大小、学习率等常用配置。

模型特有的关键参数默认折叠，需要时可展开。“专家参数”窗口包含当前模型和数据模块
公开的全部参数，支持按中文名、参数名或帮助文本搜索，也可以只看已修改项。模块推荐值
只负责提供起点；与实际实现矛盾的参数会在启动前阻止运行。

四项选择是联动的，例如 CycleGAN → 双类 → Stack 后，可选择无额外损失、结构保持、
阈值内容保持；Fusion 下支持结构保持或关闭额外损失。CUT 的 PatchNCE 是基础目标，
不是一个独立的“额外损失模型”。生成器骨干 `netG` 和融合版本 `spif_arch` 可在专用/专家参数中调节。

“单类”指一种图像来源，不是灰度：单类 RGB 仍是 `input_nc=3`；双类 BF + AF 在当前
数据实现中为两张灰度图，`input_nc=2`。Pix2Pix 另有“任务适配”选择，区分常规转换与
Lab 着色。切换组合会重置组合相关参数，保留路径、实验身份与训练计划。

模型目录与完整新旧命名表见 [`models/README.md`](../models/README.md)。旧
`cycle_gan_fusion` 实际未执行融合，只在导入旧配置时以兼容模块保留，不作为新的 Fusion 选项。

启动前会检查数据目录、通道数、裁剪尺寸、设备编号、检查点和训练初始化方式。命令预览
始终显示实际执行的统一入口及完整参数，配置保存为 schema 3 JSON，记录组合 ID 与组成元素。
旧 schema 2 JSON 可直接载入；能够准确对应的旧名称自动归类，其余保留旧参数与实现并显示兼容提示。
“读取权重配置”会从实验目录的 `train_opt.json` 或 `train_opt.txt` 导入生成器结构及训练
参数，同时保留当前数据路径、输出实验名和设备，便于准确还原旧检查点或开始微调。

## 训练初始化

- 从头训练：初始化网络和优化器。
- 继续训练：从当前实验的检查点恢复；若存在
  `<epoch>_training_state.pth`，会同时恢复优化器、学习率调度器、下一 epoch 和累计步数。
- 从其他实验微调：从 `pretrained_name` 加载网络权重，在新的实验目录中建立优化器和
  调度计划。支持设置判别器冻结 epoch；不支持冻结的模型会给出明确错误。

CUT 一类需要首批数据建立特征网络的模型通过能力钩子自动初始化，不再使用单独训练脚本。

## 数据目录

无配对训练：

```text
<dataroot>/trainA/
<dataroot>/trainB/
```

双通道训练：

```text
<dataroot>/trainA_BF/
<dataroot>/trainA_AF/
<dataroot>/trainB/
```

双通道推理：

```text
<dataroot>/testA_BF/
<dataroot>/testA_AF/
```

BF 与 AF 文件必须同名。普通单目录推理选择 `single`，并直接把图像目录作为
`dataroot`；若 `single` 与 `input_nc=2` 组合，则数据模块读取
`<dataroot>_BF` 与 `<dataroot>_AF` 两个同名前缀目录。

## 运行反馈

训练和推理引擎会输出 `@@MLCGUI` 结构化事件。控制台据此显示总体进度、当前 epoch、
损失表、损失趋势、用时和最新输出图像；普通 stdout/stderr 仍完整保留在日志页。
关闭界面不会在主线程中执行网络代码，运行中的任务可以主动停止。

## 扩展模块

推荐将实现放入 `models/<架构>/`，再在 `models/registry.py` 中登记实现和组合，四项选择会同步更新。
旧式 `models/<name>_model.py` 插件仍会自动发现，在“兼容 / 自定义插件”区域显示，并读取其参数钩子。
未知模块会使用通用说明和默认建议，但仍可从专家参数页配置。若模块的生成器检查点命名
不是 `G` 或 `G_A`，需要在推理常用配置中调整“检查点网络后缀”。

新增 `data/<name>_dataset.py` 也会以同样方式被发现。界面的目录结构说明只覆盖已登记
的数据模块；自定义数据模块的真实约束仍由其实现和参数钩子决定。
